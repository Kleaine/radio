# 审查修复报告 — Round 3

> 审查视角：Claudio 产品视角 + 新 AI 接手视角
> 日期：2026-05-31

---

## 发现的核心问题

当前设计是一个**聊天机器人**（用户打字 → AI 回文字 + 推荐歌单），不是 **AI 电台**（用户说话 → DJ 生成播报计划 → 歌曲和 TTS 交替播放）。

---

## 修复详情

### 1. 加广播计划类型

**问题**：只有 `ChatReply { say, songs[], segue }`，无法表达"先说开场白 → 放歌 → DJ 串场 → 再放歌"的顺序序列。

**文件**：`llm.service.ts`

**修复**：新增 `PlayableItem` 和 `PlanResponse` 类型：

```typescript
export interface PlayableItem {
  type: "song" | "tts";  // 歌曲 或 DJ 语音
  // song 字段
  title?: string;
  artist?: string;
  query?: string;        // 搜索关键词
  reason?: string;       // 选曲理由
  songId?: string;       // enrich 后补全
  coverUrl?: string;     // enrich 后补全
  audioUrl?: string;     // enrich 后补全
  // tts 字段
  text?: string;         // DJ 说话文本，分工4 TTS 合成
}

export interface PlanResponse {
  summary: string;
  scene: string;
  items: PlayableItem[]; // 顺序序列
  memory?: MemoryEntry[];
  schedule?: ScheduleEntry[];
}
```

### 2. 加 generatePlanStream 和 generatePlan

**问题**：只有 `chatStream` / `chat`，没有播报计划的生成入口。调度器没有 API 可调。

**文件**：`llm.service.ts`

**修复**：新增两个方法：
- `generatePlanStream(trigger, input, context, onChunk)` — 流式生成播报计划
- `generatePlan(trigger, input, context)` — 非流式，给后台调度用

`trigger` 参数让 AI 区分"用户要求的"和"系统自动生成"，生成合适的 DJ 话术。

### 3. plan-system.md 改为电台播报计划格式

**问题**：prompt 让 AI 输出 `{ say, songs, segue }`——聊天回复格式，不是电台节目序列。

**文件**：`plan-system.md`

**修复**：输出格式改为 `items[]` 序列：
```json
{
  "items": [
    { "type": "tts", "text": "早上好！今天有点阴，先从轻一点的歌开始。" },
    { "type": "song", "title": "晴天", "artist": "周杰伦", "reason": "轻快温暖" },
    { "type": "tts", "text": "接下来这首是最近你常听的风格" },
    { "type": "song", "title": "好久不见", "artist": "陈奕迅", "reason": "延续温暖氛围" }
  ]
}
```

DJ 话术以 `tts` 项穿插在歌曲之间，形成完整的电台节目序列。

### 4. 加 plan-enrich.ts 辅助函数

**问题**：AI 输出歌名 → 搜歌补 ID → 拿播放 URL 这条链路只在文档里画了，代码里没有。

**文件**：`plan-enrich.ts`（新建）

**修复**：新增 `enrichItems(items, config)` 函数：
- song 项：取 `query` → `musicService.search()` → 补全 `songId`、`coverUrl`、`audioUrl`
- tts 项：调用 `ttsService.synthesize(text)` → 补全 `ttsAudioUrl`（分工4 未对接时留空）
- 失败不崩：搜索失败保留原始信息，TTS 失败跳过

### 5. 保留 chatStream / chat

聊天流仍然存在——用户打字问"今天有什么好歌"时走 `chatStream`。电台播报和自然语言聊天两条线共存：

| 场景 | 用什么 |
|---|---|
| 用户手动触发"来点适合写代码的歌" | `generatePlanStream()` |
| 定时自动生成晨间播报 | `generatePlan()` |
| 用户闲聊"今天心情不错" | `chatStream()` |

---

## 未改动

- `schedule` 和 `memory` 字段保留在 `PlanResponse` 中。日程管理没有独立 API，聊天提取是目前唯一的路
- 通用偏好记录保留，不完全限于音乐品味
- 流式输出为主，非流式为辅
