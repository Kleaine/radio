# 意图规则表

> 分工5 — 三层意图分发规则定义
> 分工2 在后端 `/api/dispatch` 路由中按此规则实现

---

## 规则总览

用户输入的每一句话，按以下三层层级依次匹配。命中即停，不再往下走。

```
用户输入
  │
  ├─ 第1层：指令匹配（正则）→ 直接控制播放器
  │   命中即返回，不走 LLM
  │
  ├─ 第2层：搜索意图（正则）→ 直接调音乐搜索
  │   命中即返回搜索结果，不走 LLM
  │
  └─ 第3层：自然语言 → 组装上下文 → 调 LLM → 流式返回
      前两层都没命中才走这里
```

---

## 第1层：指令匹配（正则）

匹配这些指令，直接调用 `/api/player/*` 接口。

| 正则 | 匹配示例 | 动作 |
|---|---|---|
| `/下一首\|切歌\|next\|skip/i` | "下一首"、"切歌"、"next" | 播放下一首 |
| `/上一首\|previous\|prev/i` | "上一首"、"prev" | 播放上一首 |
| `/^暂停$\|^pause$/i` | "暂停"、"pause" | 暂停播放 |
| `/^播放$\|^play$\|^继续$\|^resume$/i` | "播放"、"继续" | 恢复播放 |
| `/随机\|shuffle/i` | "随机播放"、"shuffle" | 切换随机模式 |
| `/循环\|单曲循环\|repeat/i` | "循环"、"单曲循环" | 切换循环模式 |

---

## 第2层：搜索意图（正则）

匹配以下模式，提取关键词后直接调用 QQ 音乐搜索 API。

| 正则 | 匹配示例 | 提取关键词 |
|---|---|---|
| `/^(播放\|搜索\|搜\|找\|来一首?\|听)\s+(.+)/` | "播放周杰伦"、"搜索晴天"、"来首钢琴曲" | 第2个捕获组 |
| `/^(.+)的歌$/` | "周杰伦的歌" | 第1个捕获组 |

**排除规则**：如果输入包含"推荐"，跳过第2层直接走第3层。例如"推荐几首歌"虽然是自然语言，但"推荐"不走搜索。

---

## 第3层：自然语言（调 LLM）

前两层都没命中时，走此路径：

1. 调 `context.service.ts` 组装上下文（时间、天气、日程、播放历史、用户画像）
2. 调 `llm.service.ts` 的 `generatePlanStream()` 流式生成播报计划
3. 调 `plan-enrich.ts` 的 `enrichItems()` 将 AI 返回的 song 项补全真实 ID 和封面
4. SSE 流式推送文本和最终的 `PlanResponse` JSON 给前端

---

## 分发流程图

```
POST /api/dispatch { message: "好累想听点轻松的" }
  │
  ├─ 1. 遍历第 1 层正则 → 未命中
  ├─ 2. 遍历第 2 层正则 → 未命中（含"推荐"不匹配搜索）
  │
  └─ 3. 走 LLM
       ├─ context.build(message)
       │   ├─ 时间：2026-05-31 22:00
       │   ├─ 天气：22°C 小雨
       │   ├─ 日程：无
       │   └─ 用户画像：喜欢轻音乐、爵士
       │
       ├─ llm.generatePlanStream("manual", message, context, onChunk)
       │   ├─ SSE 流式推送 "好嘞～今天有点晚了……"（逐字）
       │   └─ 返回完整 PlanResponse
       │
       └─ SSE push { type: "done", data: PlanResponse }
```

---

## 补充说明

- 正则匹配是精确匹配，不处理同义词。用户说"给我停一下"会漏到第3层，但不影响功能（多等2秒）
- 第1层和第2层响应 < 1ms，第3层响应 ~3-5 秒
- 前端在等待第3层时应显示"小雨思考中…"的 loading 状态
