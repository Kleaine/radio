## 2026-06-11 修复记录：ASR 语音识别 + 录音按钮双故障

> 修复日期：2026-06-11
> 修复内容：录音再点击停止失效 + ASR 永远返回"未能识别出语音内容"

### 问题 1：录音再点击无法停止（前端状态竞态）

| 项 | 说明 |
|----|------|
| **症状** | 用户点录音开始说话，再点一次按钮录音不停，UI 无反馈 |
| **根因** | `isRecording` 单一变量管理状态。`getUserMedia` 是异步的（需要用户授权，耗时 200-1000ms），期间用户点击停止 → `recorder` 还不存在 → 静默失败，UI 卡在录音态 |
| **影响文件** | `apps/web/app.js` |
| **修复** | 引入三态状态机：`{ isStarting, isRecording, cancelled }`。启动前置 `isStarting = true`，getUserMedia 成功后置 `isRecording = true`。用户在 `isStarting` 期间点击停止 → 设 `cancelled = true`，getUserMedia 回调检查到 `cancelled` 立即释放资源。录音期间点击 → 正常 `recorder.stop()`。 |
| **验证** | 快速点击"开始→停止→开始→停止"四次，UI 都能正确切换 |

### 问题 2：ASR 永远返回"未能识别出语音内容"（WebM + ffmpeg 依赖）

| 项 | 说明 |
|----|------|
| **症状** | 录音上传后，ASR 接口返回 text=""，前端显示"未能识别出语音内容" |
| **根因** | 两条链路的不匹配：<br>1) 前端用 `MediaRecorder` 默认输出 **WebM (Opus)** 格式<br>2) Python ASR 服务用 `soundfile.read()` 读取 → 但 soundfile 不支持 WebM<br>3) ASR 代码中有 ffmpeg 回退，但 ffmpeg 未安装<br>4) Whisper 收到空音频 → 返回空字符串 |
| **影响文件** | `apps/web/app.js`、`apps/server/src/routes/chat.routes.ts` |
| **修复** | 两部分同时修复：<br>**前端**：弃用 `MediaRecorder` 输出 WebM，改用 `AudioContext + ScriptProcessor` 直接采集 16kHz PCM 样本，手动编码为标准 WAV（RIFF/WAVE header + 16-bit PCM），零外部依赖，Python `soundfile` 直接可读。<br>**后端**：`performASR()` 弃用手动拼接 multipart boundary，改用 `form-data` npm 包（`form.append("file", buffer, { filename, contentType })` → `form.pipe(http.request)`）流式上传。 |
| **代码行** | 前端 `app.js: _recStart(), _recStop(), _wavEncode()`<br>后端 `chat.routes.ts: 96-165 (performASR)` |
| **新增依赖** | `npm install form-data`（后端） |
| **验证** | `python _test_e2e_pipeline.py` → ASR 服务直接接受 WAV 返回 `status=ok` + 正确 text |

### 修复后的数据流（语音→文字闭环）

```
用户点击按钮
  ↓
  [前端] getUserMedia → AudioContext (16kHz)
          → ScriptProcessor 采集 Float32 样本
          → _wavEncode() 编码 WAV (44B header + PCM)
          → fetch POST /api/asr (multipart/form-data + JWT)
  ↓
  [Node 后端] multer 接收 audio buffer
          → performASR(): form-data 包构造请求
          → http.request POST :5000/recognize/file
          → 解析 JSON，提取 text
          → 返回 { code: 200, data: { text: "..." } }
  ↓
  [前端] 输入框填入 text，等待用户点击发送
          → 用户点击发送 → 走 /api/dispatch 文本链路
          → AI 生成播放计划 → 歌曲播放
```
